# 单插件独立更新：设计与改造计划

状态：设计稿（0.1.29 候选，未实现、未发布）

## 1. 现状与限制

| 环节 | 现状 | 影响 |
| --- | --- | --- |
| 渲染代码 | `Loader/Renderer/index.js` 在构建时把 P-Sign、Prism、自定义背景打进一个 `window-effects.js` | 任一内置插件的界面改动都必须发新版 App |
| 安装 | `PluginLibrary.installArchive` 直接拒绝内置插件：`内置插件由 Packpier 更新` | 内置插件无法单独替换版本 |
| 本地包 | 同 ID 已安装时只允许相同版本，否则报 `已安装其他版本` | 不能升级，也不能回滚 |
| 目录 | 版本信息只来自 `package.json`；市场 `catalog.json` 随 App 打包 | 没有“某个插件有新版本”的检查通道 |
| 服务 | Prism/背景的数据服务已经是 Swift 原生代码 | 只换插件包无法改变服务逻辑，需要宿主能力版本 |

结论：**只改安装器不够。** 内置插件的界面代码必须先变成“可按插件单独加载的运行时产物”，单插件更新才有意义。

## 2. 目标

- 每个插件有独立版本，可单独更新，不要求升级 App。
- 更新某个插件时保留其他插件的顺序、开关、Prism 配色、背景收藏和授权记录。
- 更新失败自动回滚到旧版本，并保持窗口原状。
- 内置插件与第三方插件共用同一套更新机制；内置插件仍禁止删除。
- 更新包可校验来源与完整性；离线时不影响已安装版本。

## 3. 核心改造

### 3.1 渲染包按插件拆分

已验证：Codex 页面的 CSP 会拦截 `data:` 和 `blob:` 的动态 `import()`，所以不能运行时 import ESM。改为每个插件产出一个**自包含 IIFE**：

```js
// renderer.bundle.js（构建产物，随插件包分发）
globalThis.__PACKPIER_DEFINE__("prism", { activate, css });
```

宿主注入顺序：

1. 注入一次很小的 `runtime.js`（服务、设置面板、`__PACKPIER_DEFINE__` 注册表）；
2. 对每个启用插件，从**已安装目录**读取 `renderer.bundle.js` 注入；
3. `__PACKPIER__.apply(state)` 按注册表挂载/卸载。

运行时宿主不再 import 任何插件源码，`window-effects.js` 从约 260 KB 降到十几 KB。

### 3.2 插件包格式 v2

```json
{
  "name": "prism",
  "version": "0.1.13",
  "packpier": {
    "apiVersion": 3,
    "minHostVersion": "0.1.29",
    "entrypoints": { "renderer": "renderer.bundle.js", "node": "backend.js" }
  }
}
```

- `entrypoints.renderer` 必须指向预构建 IIFE，不再接受 ESM 源码。
- 旧包没有该文件时只显示在市场中，不挂载（与现在第三方渲染包的现状一致）。
- 构建脚本为三个内置插件分别生成 `renderer.bundle.js`，同时打进 App 与市场 ZIP。

### 3.3 宿主按包加载

`WindowHost` 的窗口计划从 `{id, dataDirectory}` 扩展为：

```json
{ "id": "prism", "directory": "/…/packages/prism", "renderer": "/…/renderer.bundle.js", "dataDirectory": "…" }
```

注入前校验：路径在插件目录内、文件大小上限、无符号链接。读取失败时回退到 App 内置副本（仅内置插件），并报告错误。

### 3.4 单插件更新通道

签名清单（Ed25519，复用 Sparkle 发布密钥体系）：

```json
{
  "schema": 1,
  "plugins": [
    { "id": "prism", "version": "0.1.13", "minHostVersion": "0.1.29",
      "url": "https://github.com/.../prism-0.1.13.zip",
      "sha256": "…", "notes": { "zh-Hans": "…", "en": "…" } }
  ]
}
```

流程：

1. 「检查插件更新」拉取清单，校验签名与 `minHostVersion`。
2. 行内显示「可更新 0.1.13」；用户确认后下载 ZIP。
3. 校验 SHA-256 → 安全解包到暂存目录 → 校验清单与 `apiVersion`。
4. 原子替换 `packages/<id>`，保留 `package-settings.json` 的 `priorityOverride` 与 `app-state.json` 的启用状态。
5. 通知宿主重新加载该插件的渲染包；挂载失败则恢复旧目录并重新挂载旧版本。
6. 成功后清理旧版本；失败保留现场并提示日志位置。

内置插件允许走同一流程，但只接受**签名清单**或用户明确确认的本地 ZIP；删除仍然禁止。

### 3.5 界面

- 插件行：`内置 · v1.3.1`，有新版本时显示「更新到 1.3.2」。
- 详情页：新增「检查更新」「更新日志」「回滚到上一版本」。
- 设置与更新：新增「插件更新」区块（自动检查开关、上次检查时间、全部更新）。
- 更新过程不阻塞其他插件；进度显示在对应行内。

### 3.6 服务与宿主能力

内置 Prism/背景的数据服务在 Swift 里。插件包只能更新界面层，因此：

- 清单带 `minHostVersion`；涉及新 RPC 的插件必须在更高版本 App 才能更新。
- 宿主按版本暴露能力表，插件调用未知方法时返回明确错误，不崩溃。
- 第三方 Node 后端继续走系统 Node 22+ 与授权流程，不受本次改造影响。

## 4. 分阶段实施

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 拆分渲染包（runtime + 每插件 IIFE），宿主按包加载，App 行为不变 | 三个效果与现在逐像素一致；无 Node；退出清理为 0 |
| 2 | 本地 ZIP 单插件替换 + 状态保留 + 失败回滚 + 界面按钮 | 只更新 Prism，配色/顺序/开关不变；坏包自动回滚 |
| 3 | 签名清单、下载、校验、检查更新与全部更新 | 断网不影响已装版本；篡改包被拒绝 |
| 4 | 内置插件更新开关、更新日志、文档与发布流程 | 只发插件 ZIP 即可让内置插件升级 |

## 5. 风险

- **格式破坏性变更**：现有市场 ZIP 需要重建并包含 IIFE；旧第三方渲染包不再挂载。
- **CSP**：已确认只能注入 classic script，不能 import；运行时必须保持 IIFE。
- **回滚原子性**：目录替换与宿主重载之间要有失败恢复；宿主需要支持“只重载一个插件”。
- **服务兼容**：插件界面与 Swift 服务的协议要版本化，避免新插件调用旧宿主不存在的方法。
- **签名与密钥**：清单签名私钥与 Sparkle 发布密钥分开管理；公钥写进 App。
- **体积**：每插件独立 bundle 会比合并包略大，但仍在几十 KB 量级。

## 6. 不在本次范围

- Windows 版。
- 插件市场云端托管与审核后台。
- 第三方插件界面的沙箱隔离（仍与 App 同等信任，依赖安装前审阅与签名）。
